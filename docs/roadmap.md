# 路线图

顺序按「离用户的痛点远近」排，不按实现难度排。

## 1. 桌面版剩余像素差

- 项目详情页与项目悬停卡：桌面版没有可对照帧，先找用户补一张，再决定是否重做。
- 权限菜单 / 会话菜单：网页版与桌面版条目不同，几何按同类表面推断，待桌面帧校正。
- 输入卡「极窄窗」分支：< 640px 时宿主结构会变，需要独立一轮实测。

## 2. 主题与可访问性

- 浅色主题逐控件复核（新组件默认只按深色验收，浅色靠令牌推导）。
- 键盘路径补全：项目行、会话菜单、推理强度滑块的 `Home`/`End`/`PageUp` 已有，剩下
  `aria-activedescendant` 与屏幕阅读器播报文案。
- `prefers-contrast: more` 下的边界色（当前只做了 4.5:1 的常规审计）。

## 3. 证据与 CI

- 把 `docs/*.json` 的采集结果换成**脱敏 fixture**（几何数值保留、标题与路径替成示例），
  让 `npm test` 能在 CI 里跑，而不是只留在维护者机器上。
- GitHub Actions 先跑 `npm run check:core` + `npm run test:core`；证据测试作为可选 job。
- 采集脚本统一走 `--url`，把「隔离实例 + 示例数据」的搭建步骤脚本化，减少人工步骤。

## 4. 发布

- 去掉 `private: true`、补 `repository` / `homepage` 字段，发 npm 包（`files` 已经只含
  `lib`、`presets`、`cordis.patch.yml`、`skin.json`、`README.md`）。
- 版本号与 [CHANGELOG](../CHANGELOG.md) 用同一套里程碑编号（M1–M9、P0-x）。
- 插件市场条目用 [about 文案](about.md)。

## 5. 明确不做

- 不接管宿主的面板布局、不改宿主的执行步骤 / 任务 / 目标结构。
- 不迁移参考里有、DSH 没有的功能（语音、录音等）。
- 不做全局样式注入或主题 id 注册（会破坏「卸载即还原」）。
